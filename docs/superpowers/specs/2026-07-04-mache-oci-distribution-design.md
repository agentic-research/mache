# mache OCI distribution — design

- **Beads:** mache-33dc5f (bundle leyline in the image), mache-2c33b6 (doc rule-count drift), + OCI producer-side (server.json `packages[]`, feeds cloister ADR-0038)
- **Date:** 2026-07-04
- **Related:** v0.13.0 shipped runtime leyline auto-download for the *binary* path (mache-0ed19b); this is the *container* complement. Cloister ADR-0038 defines the consumer of `packages[].oci`.

## Problem

mache has no published OCI image. `task image` builds `mache.tar` **locally
only** (no `ghcr`/`docker push`/`apko publish` in CI), and that image is
**distroless, mache-only** (`melange.yaml`: "No ley-line linkage"). Consequences:

1. **No containerized LLO.** A container running mache has no leyline, so it
   falls back to tree-sitter (5 rules) — the container equivalent of the gap
   mache-0ed19b closed for binaries.
1. **`packages[].oci` has nothing to point at.** cloister sources mache via a
   hand-written `image = "mache:0.8.0"` in `cluster.toml` (that's *why* it
   silently drifted 4 versions stale).
1. **Docs claim a stale rule count** ("9 find_smells rules"; the registry has
   14).

`kiln` (now **archived** — the user retired it to avoid its auto-loading
behavior) previously solved #1/#2 and is the proven **blueprint** for how: it
built a leyline-bundled multi-arch image and pushed it to
`ghcr.io/agentic-research/mache`. This design brings that capability
**in-repo** (mache self-publishes on release), plus the `packages[]`
declaration and the doc fix.

## Ground-truth constraints (verified)

- **kiln blueprint** (`~/remotes/art/kiln`, archived): `Dockerfile.release` +
  `release.yml` image job. Key lesson: the image is **`debian:bookworm-slim` +
  `ca-certificates` + `libsqlite3-0`**, NOT distroless — because the **leyline
  (Rust) binary dynamically links libsqlite3**. Bundling leyline therefore
  rules out mache's distroless apko path for the published image.
- **kiln's exact image recipe** (to port): per-arch dirs `image/linux-{amd64,arm64}/`,
  `mv <bin>-linux-<arch> → <bin>` + `chmod +x` for both mache and leyline,
  `docker/build-push-action` with `platforms: linux/amd64,linux/arm64`,
  `file: Dockerfile.release` using `ARG TARGETARCH` → `COPY image/linux-${TARGETARCH}/{mache,leyline} /usr/local/bin/`, then `cosign sign` (keyless, `id-token: write`) + SLSA provenance.
- **ley-line-open** publishes `leyline-linux-amd64` + `leyline-linux-arm64` at
  the version pinned by `internal/leyline/socket.go:leylineBinaryVersion`
  (currently `v0.5.7`).
- **mache release.yml** already builds a binary matrix (darwin-arm64,
  linux-amd64, linux-arm64; `CGO_ENABLED=1`) uploading artifacts, then a
  `release` job. The linux mache artifacts are available in-workflow.
- **server.json** uses MCP registry schema `2025-12-11`; has `remotes`, **no
  `packages`**; `name: io.github.agentic-research/mache`, version single-sourced
  from `internal/buildinfo/version.txt` and generated by `tools/server-json-gen`
  from `internal/mcpregistry`.
- **ADR-0038 `packages[]` shape**: `{registryType, identifier, version}`;
  cloister derives `image = "<identifier>:<version>"` (operator `ext.image`
  wins; loud warn if neither).
- **ghcr.io** is free for public images; `GITHUB_TOKEN` with `packages: write`
  pushes to `ghcr.io/agentic-research/mache` — no new secrets.

## Design

Three components. C1 and C2 land together (a release then produces the image
*and* a server.json that declares it, version-coherent by construction). C3
(docs) is independent.

### C1 — leyline-bundled multi-arch image, published on release

Port kiln's proven recipe into mache's `release.yml` as a new `image` job that
`needs: build` (tag-triggered):

1. Download the matrix-built `mache-linux-{amd64,arm64}` artifacts into
   `image/linux-{amd64,arm64}/`.
1. Download the pinned `leyline-linux-{amd64,arm64}` from ley-line-open
   (`leylineBinaryVersion`, read from `internal/leyline/socket.go` so it can't
   drift) into the same per-arch dirs.
1. `mv`/`chmod +x` mache + leyline per arch (kiln's "Prepare binaries" step).
1. `docker/login-action` → ghcr with `GITHUB_TOKEN`; `docker/setup-buildx-action`;
   `docker/build-push-action` `platforms: linux/amd64,linux/arm64`,
   `file: Dockerfile.release`, tags `ghcr.io/agentic-research/mache:${TAG}` +
   `:latest`.
1. `cosign sign --yes` the pushed tag (keyless; `id-token: write` permission +
   `sigstore/cosign-installer`). SLSA provenance via the buildx attestation.

**New file `Dockerfile.release`** (adapted from kiln): `FROM debian:bookworm-slim`,
install `ca-certificates` + `libsqlite3-0`, create uid/gid 65532 `mache` user,
`ARG TARGETARCH`, `COPY image/linux-${TARGETARCH}/{mache,leyline} /usr/local/bin/`,
`chmod +x`, `USER mache`. leyline lands on PATH so mache's `LookPath("leyline")`
finds it → **LLO in-container, zero runtime download.** Entrypoint: `mache serve`
(the container's job is to serve MCP); revisit if a wrapper is needed for
data-dir setup (port kiln's `entrypoint.sh` only if required).

**Permissions** the job needs: `packages: write` (push), `id-token: write`
(cosign keyless + SLSA), `contents: read`.

**mache's existing distroless `apko.yaml`/`melange.yaml`/`task image`** stay for
the mache-only local-dev image (no libsqlite3/leyline needed there). The
published leyline-bundled image is the Dockerfile.release path. Note the two
side-by-side in a comment so a future reader doesn't think one supersedes the
other.

### C2 — `packages[].oci` in server.json

`tools/server-json-gen` (and the `internal/mcpregistry` source it reads) emit a
top-level `packages` array:

```json
"packages": [
  { "registryType": "oci",
    "identifier": "ghcr.io/agentic-research/mache",
    "version": "<buildinfo.Version>" }
]
```

`version` is single-sourced from `buildinfo.Version` (→ `version.txt`), so
`task gen:version` keeps it in lockstep with the pushed image tag — the
stale-tag class of bug closed at the source. `gen:server-json:check` (already a
CI gate) enforces server.json is regenerated. Field names match ADR-0038 /
the MCP `2025-12-11` schema (verify exact casing against the schema when
implementing).

### C3 — docs

- **mache-2c33b6:** fix the stale rule count. `docs/ROADMAP.md` ("9 structural
  rules" → the current 14, listed), `docs/competitive-landscape-2026.md`
  ("find_smells (9 rules)" + "four of the nine"), `docs/PRIOR_ART.md`. Frame it
  as "N rules across code/doc-drift/test families" so it stays accurate. Confirm
  the count from `cmd/smell_rules.go` at edit time.
- **OCI distribution note** in `docs/ARCHITECTURE.md` (+ README): mache
  self-publishes a leyline-bundled multi-arch image to ghcr on release and
  declares its own source via `server.json packages[].oci`; containers get LLO
  with no runtime fetch.
- Bump the touched docs' `covers-version` if a release cuts alongside (the
  docs:lint gate requires it).

## Sequencing

C1 + C2 in one PR: merge → next release tag both **publishes** the image and
ships a **server.json declaring it** at the same version (coherent by
construction). C3 can ride the same PR or land separately. First release after
merge = first published `ghcr.io/agentic-research/mache` image + first
`packages[]`-bearing server.json.

## Testing

- **C1 (image):** CI-only (runs on a real tag). Add a post-push smoke in the
  job: `docker run --rm --entrypoint /usr/local/bin/leyline ghcr.io/agentic-research/mache:${TAG} --version` (or pull-and-inspect) to
  assert leyline is present + executable in the pushed image. A local
  `Dockerfile.release` lint/build (`docker build -f Dockerfile.release`) can run
  in the normal CI on PRs with a dummy binary to catch Dockerfile syntax before
  release.
- **C2 (packages):** Go test on `server-json-gen`/`mcpregistry` asserting the
  emitted server.json contains the `oci` package with `identifier` =
  `ghcr.io/agentic-research/mache` and `version` = `buildinfo.Version`;
  `gen:server-json:check` gate catches drift.
- **C3 (docs):** manual; the rule-count is not gated by docs:lint (version +
  lang-count only), so no automated guard — leave a `note` linking
  `cmd/smell_rules.go` as source of truth.

## Out of scope

- Consumer side (cloister reading `packages[].oci`) — cloister ADR-0038's impl
  bead, not mache.
- A rule-count docs:lint check (mache-2c33b6 follow-up if desired).
- Retiring/deleting mache's distroless `apko.yaml` path — kept for local dev.
- arm64 support is IN scope (multi-arch); no further arches.
